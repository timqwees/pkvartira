# IndexNow — как работает, что реально ускоряет, чего ждать

Проект: **upgrade.pkvartira.ru** (второй сайт). Все изменения и пинги по умолчанию идут сюда.

## Что реализовано

| Компонент | Где | Что делает |
|---|---|---|
| Ключ | `public/769e1df8217a98f76286a4d39b571085.txt` + роут | отдаёт ключ; `keyLocation` = `https://<host>/769e1df8217a98f76286a4d39b571085.txt` |
| Авто-пуш | `GET /indexnow` (`setting/Route/routes.php`) | сверяет mtime страниц с состоянием, отправляет только изменившиеся |
| CLI | `php tools/indexnow.php` | разовая отправка всего сайта или списка URL |
| Состояние | `sys_get_temp_dir()/pkvartira-indexnow-state-<host>.json` | отдельный файл на каждый домен |

Отправка — **одним POST на пачку** (до 10 000 URL) на три шлюза: `api.indexnow.org`, `www.bing.com/indexnow`, `yandex.com/indexnow`.
Раньше был один запрос на каждый URL: 55 адресов = 36 секунд. Сейчас 114 адресов = 2,4 секунды.

Не отправляются намеренно: `noindex`-страницы, 301-редиректы (`/kalkulyator-ploshchadi`), `/search`,
`/soglashenie`, `/other`, вакансии. Блог отправляется на обоих доменах: canonical у каждой страницы
self-referencing на своём хосте.

## Проверка

```bash
# что уйдёт, без отправки
php tools/indexnow.php --dry-run

# отправка (по умолчанию upgrade.pkvartira.ru)
php tools/indexnow.php

# состояние на проде
curl -s https://upgrade.pkvartira.ru/indexnow | jq '.checked, .sent_count'
```

Коды ответа: **200/202** — принято, **403** — ключ не найден по `keyLocation`,
**422** — URL не принадлежит хосту, **429** — слишком часто.

Защита от злоупотребления: если задать `INDEXNOW_TOKEN` в окружении, эндпоинт требует `?token=…`.

## Canonical

Все страницы upgrade.pkvartira.ru отдают **self-referencing canonical на upgrade** и ничего не
перенаправляют на pkvartira.ru — каждая страница второго сайта самостоятельно борется за выдачу.

## Честно о сроках: «мгновенно» не бывает

IndexNow — это **сигнал «переобходи страницу»**, а не команда «переиндексируй сейчас».

| Поисковик | Поддержка IndexNow | Реальный срок | Что реально ускоряет |
|---|---|---|---|
| Bing | да, родная | от 15 минут до 24 часов | IndexNow + корректный sitemap |
| Yandex | да | обычно часы–дни | IndexNow + «Переобходим страницы» в Вебмастере (надёжнее) |
| Google | **нет** | дни–недели | только sitemap + внутренние ссылки + Search Console |
| Seznam, Naver | да | часы | IndexNow |

Выводы:
1. Для **Bing** IndexNow работает хорошо — это его родной протокол.
2. Для **Яндекса** IndexNow работает, но гарантированно быстро — только через API Вебмастера
   (`Переобходим страницы`), для этого нужен OAuth-токен и подтверждённый сайт в Вебмастере.
3. Для **Google** IndexNow бесполезен. Там работают: свежий `lastmod` в sitemap, ссылки со своих
   страниц и запрос через Search Console. Обещать мгновенную индексацию в Google нельзя.

## Что нужно для максимальной скорости (в порядке важности)

1. **Cron на эндпоинт** — сейчас пуш не запускается сам, его надо дёргать:
   ```
   */30 * * * * curl -s -o /dev/null https://upgrade.pkvartira.ru/indexnow
   ```
   Задача дешёвая: если изменений нет, отвечает за 0,05 с и ничего не отправляет.
2. **`robots.txt` на upgrade** — сейчас отдаёт бесконечный 301 на самого себя (nginx). Пока поисковик
   не может прочитать robots, скорость обхода падает. Правится в nginx на сервере, не в репозитории.
3. **Вебмастер Яндекса** — подтвердить upgrade.pkvartira.ru и настроить «Переобходим страницы»:
   это единственный способ получить предсказуемо быструю переиндексацию в Яндексе.
4. **Sitemap в обоих Вебмастерах + Bing Webmaster Tools** — без отправленной карты IndexNow
   работает «в пустоту»: пинг не заменяет карту.
5. **Не пинговать чаще раза в сутки один и тот же URL** — Bing рекомендует именно так,
   иначе пинг игнорируется.

## Скорость обновлений при правках

Пуш смотрит на `mtime` файлов. Значит:
- правка шаблона/`articles.json` → при следующем вызове `/indexnow` адрес уйдёт;
- после деплоя mtime у всех файлов свежий → в первый вызов уйдёт весь сайт (это нормально один раз);
- если контент меняется в БД и `mtime` файлов не трогается — пуш этого не увидит.
  Для таких страниц нужен явный вызов: `php tools/indexnow.php --file=urls.txt`.
